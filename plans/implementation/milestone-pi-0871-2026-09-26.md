# Milestone: Pi 0.87.1 selected transport — 2026-09-26

This milestone closes the local Windows Pi 0.87.1 integration slice, not the
integral Nexus Connector Core plan. All code the Core needs is owned by this
repository; no runtime import or path reference to the sibling Nexus checkout
is required.

Delivered:

- The Core-owned Pi adapter uses exact response-ID/verb correlation for the
  observed 0.87.1 package; older ID-less observations retain bounded
  serialized fallback. A stale `agent_settled` before a new `agent_start`
  cannot settle the new receipt.
- Explicit local selection of Node plus the installed Pi package CLI binds
  both files in a composite fingerprint. Version observation and launch
  preparation probe `node cli.js`, not the Node interpreter alone.
- One user-authorized real Pi turn, with tools disabled and a disposable
  session, reached `agent_settled` with assistant stop reason `stop`. No
  further provider turn was made.
- Rejected `prompt`, `steer`, and `abort` responses fail the adapter send.
  Because command bytes were written, the Core journal conservatively keeps
  possible-effect unknown rather than recording a false submitted receipt.

Verification: focused Pi/bridge suites passed 68 tests plus one platform
skip in each local Windows/WSL2 × Python 3.11–3.13 environment. Full Python
3.13 suites passed Windows 598/73 and WSL2 657/14 (passed/skipped), each
with the known injected legacy thread warning. Normalized wheel/sdist bytes
matched across Windows and WSL2; strict Twine, clean-wheel consumers and
offline installs in all six local environments passed. The development
release gate reports `publishable: false`.

Production native qualification is still disabled. Remaining K06 work
includes public ID-less Pi steer/follow-up targeting, extension UI/error
campaigns, retry/compaction/cancel/shutdown under a real provider, Linux
provider behavior and host consumer integration. The broader K00–K11 gates
remain in progress; see [status](status.md) and [acceptance matrix](matrix.md).
