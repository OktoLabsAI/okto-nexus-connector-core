# PC12 + PC13 + PC14 — Attach, integração, migração e artefatos (C1)

## PC12 (G04) — attach pela API pública (trilha própria)

- Tipos públicos `AttachTarget` (evidência de alvo aprovada pelo host,
  identidade verificável bornada) e `AttachPolicy` (semântica detach-only:
  revogar handles, nunca matar a árvore externa). `prepare(mode=attach)`
  falha prescritivamente com `CAPABILITY_UNSUPPORTED`; `ATTACH_QUALIFIED`
  permanece False; não existe flag de habilitação. O adapter legado
  (substrato POSIX) e sua suíte de 57 testes seguem verdes no WSL2.
  RC-12-01/02/06 BLOCKED (substrato real/hosts); RC-12-03/04/05/07 PASS
  (semânticas de nunca-matar comprovadas pelos testes PC02/PC07).

## PC13 (G06) — integração dos dois hosts

- RC-13-03/06/07/08/10/11 PASS: mesmo wheel nos dois smokes (offline),
  diagnóstico stdio-only sem fallback, extensão Pi sintética ponta a
  ponta, multi-turn/HITL/interrupt das campanhas reais autorizadas
  anteriores, restart/crash sem takeover por PID, saturação sustentada
  45s×4 sessões nos dois SOs.
- RC-13-01/02/04/05/09/12 BLOCKED: exigem as aplicações Nexus Server e
  Connector (planos N/C não iniciados, decisão do usuário). Handoff e
  factory pública prontos para pin.

## PC14 — migração, artefatos, documentação, gates

- **Migração dev0 (RC-14-01/02)**: journal dev0 com ID longo (197),
  claim+slot com gerações, eventos ACKed/não-ACKed — reabre sob o Core
  corrigido com histórico íntegro: ID legado legível pela consulta
  pública, re-abertura da mesma sessão recusada (`SESSION_CONFLICT`),
  replay idêntico, ciclos de reopen estáveis. Nada re-keyed/apagado;
  rollback = usar o wheel anterior (schema SQLite idêntico; mudanças
