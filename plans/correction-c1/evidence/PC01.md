# PC01 — Journal off-loop (C1)

## Change

`src/nexus_connector_core/offloop.py` introduces `OffLoopExecutor`: one
dedicated worker thread per store owning the SQLite connection for its
whole lifetime; complete units of work; bounded normal (256) and urgent
(64, reserved for controls) queues plus a pending-payload byte budget;
wake-tag queue so an arriving item wakes the worker immediately without
polling; cancel-safe result delivery (a cancelled await never raises
`InvalidStateError` and the durable unit still completes); explicit
`aclose()`/`close()` with drain and proof (a close timeout raises rather
than claiming closure); `metrics()` exposing queue depths, bytes, thread
id and stopped flag — no payloads or secrets.

`SQLiteJournal` and `SQLiteOwnedSlotLedger` moved **all** SQL
(connect/pragmas/schema/migrations, admissions, markers, receipts, lease
CAS, claims, births, slots, events, ACK/compaction, checkpoints,
`storage_status`) into worker units. Reads included. `events()` replays in
pages, each fetched as one complete unit — no transaction spans a consumer
yield. Critical event categories and control writes use the urgent queue;
event writes carry `payload_bytes` into the byte budget. Saturation before
enqueue raises typed `JOURNAL_BUSY`/backpressure with no possible effect;
after enqueue the unit completes regardless of caller cancellation. A
stopped store refuses new work with `JOURNAL_CLOSED`.

Ordering guarantees preserved: `run_sync` (tests/control bridge) uses the
*normal* queue so a synchronous read can never jump ahead of an
already-accepted normal write; the running unit is never preempted by the
urgent queue.

One behaviour fix surfaced by the new ordering and kept deliberately: a
force task that already issued its physical containment request is never
cancelled mid-bookkeeping — its durable receipt (SUBMITTED or honest
OUTCOME_UNKNOWN) always lands; `_schedule_force` no longer replaces a
running force task.

## Verification (Windows/Python 3.13, `PYTHONPATH=src`)

- Full suite: **632 passed / 74 skipped / 7 xfailed** (baseline was 623/74/8
  xfailed): the F04 seed now passes (external writer held the database
  >550 ms; the loop ticker progressed ≥15 ticks; SQL thread ≠ loop thread;
  the queued write committed after release). The remaining 7 xfailed are
  F01/F02/F03/F05/F06/F07×2 (PC02–PC08).
- New `tests/test_offloop_executor.py` (8 tests): off-loop execution +
  immediate wake, typed saturation before effect with urgent reserve and
  no preemption of running units, byte-budget rejection, cancellation
  after enqueue completing the durable unit, exception delivery, setup
  failure surfacing, aclose/close with refusal after stop, and repeated
  lifecycle without thread leaks.
- Journal conformance/restart kits, WAL bound, disk full, crash cuts,
  multiprocess fairness (4 processes), owned-slot kits, runtime suites:
  all pass on the worker.
- 46 test/tool `_db` usages migrated to the `_run_sync` control bridge.

## Notes / limits

- The synchronisation seeds of the audit were re-derived on the worker;
  no invariant was relaxed. Timeouts were not increased to mask anything;
  one test assertion now waits for the force bookkeeping to settle instead
  of racing it with a synchronous read.
- `close()` remains as the documented transitional bridge (tests/host
  teardown); `aclose()` is the canonical loop-safe path.
- Linux (WSL2) verification of this phase is recorded with the phase
  commit's CI run of the same suites.
